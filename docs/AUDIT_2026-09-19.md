## 原始问题记录（下述行为仅指审计基线）

### A01 · P1 · 目标平台字段进入产物文件路径，缺少边界校验

**位置：** [manager.go](https://github.com/LuisCMerrick/nginx-online-build/blob/2b6641d1d4e5cc3c25f0c437f2e56ead18ddf1e6/internal/builder/manager.go#L93) 的 `CreateJob`；[executor.go](https://github.com/LuisCMerrick/nginx-online-build/blob/2b6641d1d4e5cc3c25f0c437f2e56ead18ddf1e6/internal/builder/executor.go#L298) 的产物命名与 `packageArtifacts`。

`target_os`、`target_arch` 由 JSON 原样接收并拼入文件名，随后通过 `filepath.Join` 和 `os.Create` 写入。上游接口没有限定合法平台或拒绝路径分隔符。相应字段含目录穿越段时，路径可以离开当前任务的 `artifacts/`。

**证据：** 函数级探针使用与生产代码相同的文件名拼接，在临时任务目录内将目标解析为 `artifacts/` 的上级，并成功写入无害标记。API 接收到文件创建的调用链经静态核对；未对外部实例发送该请求。

**影响：** 有效密钥持有者可在服务账户有权限、父目录存在的位置创建或覆盖以 `.tar.gz` 结尾的文件。触发实际打包还需先完成编译；这不是任意后缀、任意内容写入。关闭鉴权时入口也对匿名调用者开放。

**修复：** 当前无交叉编译实现，可直接采用 `runtime.GOOS/GOARCH`，对不一致的请求拒绝受理；若保留字段则使用严格枚举。文件创建前另用 `filepath.Rel` 校验最终路径必须位于产物目录内。

**验收：** 平台含 `/`、`\`、目录穿越或不支持的值时，在创建工作目录前返回 400；正常请求的文件名与实际二进制平台一致。

### A02 · P2 · 冒烟检查忽略部分非零退出，产生成功误报

**位置：** [executor.go](https://github.com/LuisCMerrick/nginx-online-build/blob/2b6641d1d4e5cc3c25f0c437f2e56ead18ddf1e6/internal/builder/executor.go#L540) 的 `smokeTestArtifact`。

当前条件为 `err != nil && !syntaxOk`。Nginx 先报告配置语法正确、随后因 PID 路径或目录权限失败时，非零退出被忽略，任务继续标记为 `completed`。

**证据：** 为真实构建指定不存在的 PID 父目录，冒烟输出同时包含 `syntax is ok`、PID 文件打开失败和 `test failed`，API 状态仍为 `completed`。这是已实测的结果误判，与 PID 目录应由谁创建是两个问题。

**修复：** `nginx -t` 非零退出一律视为失败。测试配置应将 PID、日志和临时目录显式放入测试目录，并使用适合测试环境的账户。语法正确与运行准备完成如需分别呈现，应使用独立字段。

**验收：** 正常配置零退出通过；缺目录、权限不足、缺依赖和缺模块等场景均不得报告构建验证成功。

### A03 · P2 · 创建任务返回可变对象，响应状态存在竞态

**位置：** [manager.go](https://github.com/LuisCMerrick/nginx-online-build/blob/2b6641d1d4e5cc3c25f0c437f2e56ead18ddf1e6/internal/builder/manager.go#L151) 的 `CreateJob`；[handler.go](https://github.com/LuisCMerrick/nginx-online-build/blob/2b6641d1d4e5cc3c25f0c437f2e56ead18ddf1e6/internal/handler/handler.go#L169) 的 `handleBuilds`。

`CreateJob` 启动 Worker 后返回内部 `*BuildJob`，HTTP 响应直接读取 `job.Status`；Worker 同时可能通过 `Update` 修改该字段。`GetJob/ListJobs` 返回快照的保护没有覆盖这条路径。

**证据：** 占用唯一并发槽位，创建短超时任务并读取返回对象 Status，race detector 报告 `manager.go` 的超时状态写入与该读取竞争。生产 handler 使用相同的无锁字段读取方式。

**修复：** 创建接口返回只含不可变标识的结果，或在锁内生成状态快照。所有可变任务字段读取统一走 `Clone/Update`；内部 `PruneOldBuilds` 也有直接读取 Status 的代码，接入前需一并检查。

**验收：** 补充任务创建响应与排队超时、取消并发的测试，在 `-race` 下通过。

### A04 · P2 · 相对数据目录导致依赖源码路径解释错误

**位置：** [config.go](../internal/config/config.go) 的目录处理；[executor.go](https://github.com/LuisCMerrick/nginx-online-build/blob/2b6641d1d4e5cc3c25f0c437f2e56ead18ddf1e6/internal/builder/executor.go#L122) 的 `resolvedDepDirs` 与 configure 工作目录。

`DATA_DIR` 默认 `./data`，未转为绝对路径；依赖源码路径据此拼接。执行 configure 时 cwd 已切到 Nginx 工作树，`--with-openssl/--with-pcre/--with-zlib` 里的相对路径会从该 cwd 再解释，指向错误位置。

**验证级别：** 静态路径推导，未执行完整第三方源码依赖构建。Docker 默认 `/app/data` 不受这一默认相对路径问题影响。

**修复：** 启动时用 `filepath.Abs` 规范化数据根目录，并对创建/写入失败终止启动。README 已使用绝对路径作为当前规避方式。

**验收：** 分别用相对、绝对数据目录完成至少一次真实依赖源码构建，实际 configure 参数均指向存在的目录。

### A05 · P2 · 取消与超时没有覆盖完整生命周期

**位置：** [manager.go](https://github.com/LuisCMerrick/nginx-online-build/blob/2b6641d1d4e5cc3c25f0c437f2e56ead18ddf1e6/internal/builder/manager.go#L156) 的 `runWorker/CancelJob`；[version.go](https://github.com/LuisCMerrick/nginx-online-build/blob/2b6641d1d4e5cc3c25f0c437f2e56ead18ddf1e6/internal/nginx/version.go#L180)、[deps.go](https://github.com/LuisCMerrick/nginx-online-build/blob/2b6641d1d4e5cc3c25f0c437f2e56ead18ddf1e6/internal/nginx/deps.go#L157) 的下载函数；[app.js](../web/app.js) 的 `checkJobStatus`。

- 下载函数没有任务 context，使用独立 60/90 秒客户端超时；解压、打包也没有任务取消检查。
- cancel 函数在 Worker goroutine 内注册，任务返回到注册之间存在时间窗口；早到的取消可能只改状态而未取消执行 context。
- `CancelJob` 未设置 EndTime，后续构建阶段可能再次写入状态；应统一终态转换。
- Worker 在排队超时直接返回时未经过 `ExecuteBuild` 的 broadcaster 关闭逻辑，可能遗留日志文件与 SSE。
- 前端只将 `completed/failed` 视为轮询结束，未完整处理 `cancelled`；详情接口也继续重算取消任务的耗时。

**验证级别：** 静态调用链与状态流审查。并未进行真实慢速网络下的取消/超时测试，不声称已经测得具体停止延迟。

**修复：** 在任务公开前创建并登记 context；下载请求绑定任务 context；耗时循环检查取消；所有退出路径统一记录终态、EndTime 和关闭日志。前端将 cancelled 作为终态。共享下载需区分单个等待者取消与其他任务仍在使用的下载。

**验收：** 分别在排队、下载、解压、configure、make、打包阶段取消，确认状态稳定、执行停止、资源释放及前端恢复。

### A06 · P2 · 重启后 packaging 任务不会进入终态

**位置：** [manager.go](https://github.com/LuisCMerrick/nginx-online-build/blob/2b6641d1d4e5cc3c25f0c437f2e56ead18ddf1e6/internal/builder/manager.go#L65) 的 `loadHistoricalJobs`。

恢复逻辑只将 queued、downloading、configuring、building 标为失败，遗漏 packaging。重启后该任务保留“打包中”，但没有对应 Worker。

**证据：** 将状态为 packaging 的任务写入临时 `meta.json`，重新创建 Manager，读取仍为 packaging。

**修复：** 统一枚举所有非终态并标为中断失败，设置结束时间并持久化；对已知终态保持原值。

**验收：** 每种非终态的重启恢复都有测试，任务列表中不再出现没有 Worker 的进行中任务。

### A07 · P2 · 非法输入静默忽略，预览不能保证请求意图被接受

**位置：** [options.go](https://github.com/LuisCMerrick/nginx-online-build/blob/2b6641d1d4e5cc3c25f0c437f2e56ead18ddf1e6/internal/nginx/options.go#L579) 的 `ValidateAndBuildArgs`。

未在目录中出现的选项 ID 没有报错；部分非法路径和依赖 opt 直接跳过。调用者可能认为模块或安装路径已生效，实际得到默认参数。路径覆盖参数还通过 map 遍历输出，顺序并不保证一致。

**证据：** 提交不存在的模块 ID、含被禁止字符的 prefix 和未知覆盖字段，结果与默认参数完全相同，错误、警告、冲突列表均为空。

**修复：** 先验证所有输入，再补依赖和解决冲突。未知 ID/字段、非法路径和 opt 返回明确错误；为路径参数排序。自动调和后再次核对依赖及互斥约束。

**验收：** 输入拼写错误和非法值得到明确 400；合法参数经过规范化后可重复生成同序列结果。

### A08 · P2 · 共享管理密钥暴露面偏大

**位置：** [auth.go](https://github.com/LuisCMerrick/nginx-online-build/blob/2b6641d1d4e5cc3c25f0c437f2e56ead18ddf1e6/internal/auth/auth.go#L49)、[i18n.js](https://github.com/LuisCMerrick/nginx-online-build/blob/2b6641d1d4e5cc3c25f0c437f2e56ead18ddf1e6/web/i18n.js#L21)、[main.go](../cmd/server/main.go)。

密钥写入启动日志、URL 查询参数、前端 localStorage 和 Cookie；Cookie 明确不启用 HttpOnly，也未设置 Secure。前端虽然移除地址栏中的密钥，后续 API、语言包和 SSE URL 仍重新附带它。

**证据：** 实例响应检查确认缺少两项 Cookie 属性；前端 URL 构建及日志打印经静态核对。未声称发现了额外的 XSS 或匿名鉴权绕过。

**影响：** 读取相关日志、同源脚本存储或未加密传输的人可能取得具有同等管理能力的共享密钥。具体暴露取决于部署和日志访问权限。

**修复：** 将一次性登录凭据交换为可撤销的服务端会话，使用 HttpOnly Cookie，在 HTTPS 部署启用 Secure；API 使用请求头，SSE 使用同源会话，避免长期凭据重复进入 URL。普通启动日志不输出长期固定密钥。

**当前规避：** HTTPS、限制密钥持有人、保护启动日志、对访问日志查询参数脱敏。文档已说明此共享权限模型。

### A09 · P2 · 并发限制不能约束任务总量和数据增长

**位置：** [handler.go](../internal/handler/handler.go) 的 JSON 解码；[manager.go](../internal/builder/manager.go) 的排队及历史保留；[version.go](../internal/nginx/version.go)、[deps.go](../internal/nginx/deps.go) 的流式下载；[main.go](https://github.com/LuisCMerrick/nginx-online-build/blob/2b6641d1d4e5cc3c25f0c437f2e56ead18ddf1e6/cmd/server/main.go#L96)。

请求 JSON 未设置大小限制；排队任务数量无上限，每个任务提前创建目录和日志；源码下载无明确压缩体积限制；没有运行中的历史清理机制。HTTP 直接使用 `ListenAndServe`，未配置读请求头等超时。

**验证级别：** 静态检查；未进行压力测试或填盘测试。现有解压文件数量/体积限制有效覆盖其针对的层面，但不等于总资源配额。

**修复：** 添加请求体、队列、下载体积和总数据保留限制，明确拒绝响应；配置 ReadHeaderTimeout 等请求读取保护，保持 SSE 所需的长连接；为过期任务清理设计同步和终态约束。

**验收：** 超过各边界时明确拒绝并释放资源；清理不删除活动任务；SSE 正常工作。

## 设计边界（按修复后的实现更新）

| 事项 | 当前事实 | 文档处理 |
| --- | --- | --- |
| 任务隔离 | 每任务独立目录，同一账户及服务环境执行；容器部署也是所有任务共用一个容器 | 删除“物理沙箱隔离”保证，说明适用的可信用户模型 |
| 系统依赖安装 | 包名来自内置映射，以 `exec.Command` 参数数组执行；展示用命令字符串不是实际的 Shell 执行入口 | 没有据此认定为任意包名/Shell 注入；说明 root/sudo 与安装目标环境 |
| 源码校验 | 仅在 ExpectedSHA 非空时比较可信预期值；动态版本列表为匹配的内置条目保留哈希，自定义 URL 不接受用户提供的预期哈希字段 | 删除“全部源码强制官方 SHA 校验”；区分记录哈希、比较预期值、签名验证 |
| 自定义源码 | 下载限制不能限制 configure/make 脚本行为，且子进程继承除 AUTH_KEY 外的环境 | 说明下载的源码仍按可执行代码信任 |
| 静态链接 | 源码嵌入特定依赖库不代表所有库静态链接 | 删除“完全绿色、任意主机可运行”；要求目标环境检查 |
| 验证范围 | 版本精确匹配；参数比较要求期望参数存在，但额外参数仅记录；ldd 失败不会阻断；最小配置检查不覆盖生产协议行为 | 说明版本精确匹配、期望参数存在校验与生产部署验证的区别 |
| 产物元数据 | BUILD_INFO.json 在最终冒烟检查前创建，最终 SHA/冒烟结果应查 API 或 meta.json | 不将压缩包内快照称为最终验证报告 |
| 语言包 | 新语言可手选；浏览器自动匹配仅中文/英文；后端部分消息及鉴权页中文固定 | 修正“零代码全语言自动识别”和“完全英文界面” |
| 版本与许可证 | go.mod 为 1.24；Docker 构建使用 1.25；仓库缺少 LICENSE | 修正 Go 1.22+，删除不存在的 MIT 文件链接并说明缺项 |
